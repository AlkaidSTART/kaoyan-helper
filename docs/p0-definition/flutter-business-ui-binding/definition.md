# P0 - 业务视图真实数据绑定（flutter-business-ui-binding）

> 日期：2026-09-26
> 前置：`flutter-user-api-integration` 已完成网络层 + 六模块仓储（本任务直接复用）
> 上游契约：`docs/p1-design/next-backend-api-rbac/api-contract.md` §6~§9

## 1. 真实痛点

上一阶段后刷题/错题/择校/背诵四个视图仍是静态假数据，用户登录后看到的业务内容与后端无关，无法产生真实学习行为（答题、错题消除、复习打卡、择校收藏）。

## 2. 用户场景

- 登录后进入刷题：拉取官方公开题库作答 → 服务端判题 → 展示正确答案与官方解析 → 下一题。
- 错题页：查看本人错题（按学科/状态筛选）→ 重做（服务端判题、连对 2 次自动掌握）→ 删除/重新激活。
- 择校页：搜索真实院校库、按 985/211/双一流筛选、展开查看专业历年招生数据、星标记为目标院校（同步 ME targets）。
- 背诵页：拉取今日到期卡片 → 翻面 → 忘记/模糊/牢记（服务端 SM-2）→ 清空当日到期即自动打卡。

## 3. 范围边界

| 范围内 | 范围外 |
|---|---|
| 四视图状态层（AsyncNotifier）+ 数据绑定 + 空态/加载/错误兜底 | AI 深度解析（保留唤起 AI 面板的既有交互）、AI explain 接口 |
| 服务端判题闭环（QUIZ-03 / MIS-03）、SM-2 复习（FC-04）、打卡反馈 | UGC 建题/改题（QUIZ-04~06，后续任务） |
| 目标院校增删（SCH-04/05）与专业历年数据（SCH-03） | "开始错题攻坚"混合组卷（后端无对应接口，按钮保留提示） |
| uuid 依赖（attemptId 需 `z.uuid()` 校验） | OAuth、AI SSE |

## 4. 验收指标

1. 四视图在登录后展示真实数据；未登录/空数据/加载中/失败均有对应占位与重试，不崩溃、不显示假数据。
2. 答题/重做结果（对错、连对、掌握）完全来自服务端；客户端不提交结果字段。
3. 卡片复习走 FC-04 幂等键；当日到期清空后出现"已完成"态。
4. 择校筛选/搜索调用后端 query；星标同步服务端 targets。
5. `flutter analyze` 零问题、`flutter test` 全绿；四视图组件测试改用 Fake 仓储闭环。
