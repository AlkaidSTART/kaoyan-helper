# P0 - 管理端只读化与用户活动收集（Admin Read-only Activity）

> 日期：2026-09-26
> 上游诉求：产品方向调整（会话决策，2026-09-26）——"admin 端不执行任何操作，只需要能够看到并收集用户的活动"
> 前置任务：`docs/p0-definition/admin-backend-api/`（20 个管理接口已实现）、`docs/tasks/2026-09-26-admin-console-ui/`
> 关联任务：`docs/tasks/2026-09-26-admin-readonly-activity/plan.md`

## 1. 真实问题

1. **管理端被建成"操作台"，与产品定位不符**。当前 `/api/v1/admin` 存在 12 个变更类接口（用户封禁、UGC 通过/驳回、题目增删改、院校/专业维护、两阶段批量导入），管理端 UI 也预留了"通过/驳回""批量导入"等操作入口。产品定位收窄为**纯观察者**：管理端不执行任何操作，只看数据。
2. **用户活动没有任何收集与展示机制**。全库不存在用户活动（行为事件）模型与管理端查看界面；最接近的只有看板里从 `question_attempts` 推导的 DAU/WAU 聚合。运营无法回答"某个用户最近做了什么、什么时候登录的"。
3. **写接口无人消费，纯增攻击面**。管理端 UI 从未接线上述写接口（占位按钮只弹 toast），12 个变更接口处于"已实现、无调用方"状态，但仍然暴露在 API 面上。

## 2. 范围

| 编号 | 内容 | 类型 |
|---|---|---|
| R1 | 移除管理端全部变更能力：12 个变更接口下线，服务/仓储收敛为只读，写权限点删除 | 变更（删减） |
| R2 | 新增 `user_activities` 活动事件模型 + 移动端行为埋点（登录 / 答题 / 卡片复习） | 新增 |
| R3 | 新增 `GET /admin/activities` 只读查询接口（ADMIN-ACT-01） | 新增 |
| R4 | 管理端 UI：新增"用户活动"页（真实数据），移除 UGC 审核、批量导入等操作入口 | 新增 + 变更 |

## 3. 范围边界

- **不删除 Prisma 模型**：`SchoolImportJob`、`AdminAuditLog` 等表结构保留（不做破坏性数据库迁移），仅下线写入口；恢复能力由 git 历史承担。
- **管理端其余只读页保持现状**：概览（mock）、用户、题库、UGC 队列、院校数据页仍是只读展示，本次不接线 mock → 真实接口（原任务清单里已明确另立任务），仅移除其中的操作暗示（按钮、脚注）。
- **埋点只做服务端旁路记录**：Flutter 端尚未接入真实网络层（全部 fake 仓储），本任务不做客户端 SDK；活动事件由服务端在既有写路径上自动落库，客户端接入后即自动生效。
- **打卡活动暂不采集**：`POST /check-ins` 尚未实现，待其落地时补埋点（记录在 P2 遗留项）。
- 活动查询不做时间范围筛选与导出（沿用审计日志 ADR 口径：以最近行为主场景）。

## 4. 验收指标

1. `/api/v1/admin/**` 不再存在任何非 GET 处理器；`ADMIN_PERMISSIONS` 仅剩读权限点 + 新增 `admin:activity:read`。
2. `user_activities` 模型落地（Prisma schema + Supabase 基线 SQL 同步），登录 / 答题 / 卡片复习三条写路径在主流程成功后自动记录活动事件；采集失败不影响主流程（旁路 best-effort）。
3. `GET /admin/activities` 支持 `userId?`（UUID 校验）、`type?`（白名单）、标准分页，固定 `createdAt desc`，经 `getActor + requirePermission + assertAdminActor` 三重校验。
4. 管理端新增 `/activities` 页，展示真实数据（时间/用户/类型/摘要），支持类型筛选与翻页；UGC 页与院校页不再出现任何操作按钮。
5. `pnpm lint` / `pnpm test` 零错误零告警；被删减能力对应的旧测试同步移除，新增能力均有服务层单测。
